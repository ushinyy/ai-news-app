# 뉴스 수집기 기능 개발 워크플로

새 기능을 개발할 때 쓰는 명령입니다. 아래 단계를 순서대로 실행하세요.
브랜치 이름: $ARGUMENTS

## 1단계. 현재 상태 확인

1. `git status`와 `git branch --show-current`로 현재 브랜치와 작업 트리 상태를 확인한다.
2. main 브랜치가 아니라면 경고하고, main으로 이동할지 사용자에게 물어본다. 답을 받기 전에는 다음 단계로 넘어가지 않는다.
3. 커밋되지 않은 변경이 있으면 함께 알린다.

## 2단계. 새 브랜치 만들기

1. `$ARGUMENTS`가 비어 있으면 어떤 기능을 개발할 것인지 물어보고, 영어 소문자-하이픈 형식(예: `add-search-filter`)으로 브랜치 이름을 제안한다. 사용자가 확정하면 그 이름을 쓴다.
2. 이름이 있으면 `git checkout -b <브랜치 이름>`으로 브랜치를 만든다.

## 3단계. 개발 시작 안내

1. 브랜치 생성이 끝나면 '이제 개발을 시작하세요!'라고 안내한다.
2. `CLAUDE.md`를 읽고 이 프로젝트의 기술 스택과 컨벤션을 다시 한번 정리해서 알려 준다. 최소한 다음을 포함한다.
   - 스택: Next.js 16(App Router), TypeScript, Tailwind v4, Clerk 인증, Drizzle + Neon Postgres, Claude(Haiku), Notion MCP
   - 컨벤션: 커밋 메시지는 한글, `PRD.md`와 `ui.md`를 먼저 읽을 것, Next.js 16 breaking change 주의, 모든 데이터는 Clerk `userId`로 분리
3. 사용자가 개발을 마치고 '완료' 또는 'done'을 입력하길 기다린다.

## 4단계. 완료 처리와 커밋

사용자가 '완료' 또는 'done'을 입력하면:

1. `git status`와 `git diff --stat`으로 변경된 파일 목록을 보여 준다.
2. 변경 내용을 바탕으로 한글 커밋 메시지를 제안한다.
3. 사용자가 확인하면 변경 파일을 add하고 커밋한다. 수정을 원하면 반영해서 다시 확인받는다.
4. 커밋한 뒤 main으로 이동해 개발 브랜치를 병합한다(`git checkout main` → `git merge <브랜치 이름>`).
5. 병합 중 충돌이 나면 멈추고 사용자에게 알린다. 임의로 해결하거나 강제로 진행하지 않는다.

## 5단계. 작업 요약

병합이 끝나면 작업 내용을 요약해서 보여 준다.

- 브랜치 이름과 병합 결과
- 커밋 메시지
- 변경된 파일 목록과 각 파일의 변경 요지
